# CurlDesk 实施开发文档

## 1. 项目概述

### 1.1 项目名称

**CurlDesk**

### 1.2 项目定位

CurlDesk 是一个轻量、Local-First、跨平台的 curl 桌面工作台。

CurlDesk 不尝试成为 Postman、Bruno、Insomnia 的替代品，也不重新设计 HTTP Request Builder。

核心理念：

> Curl is the request format.

用户直接编写、保存和执行原始 curl 命令。

核心使用流程：

```text
Write Curl
    ↓
Save Curl
    ↓
Select Environment
    ↓
Run
    ↓
System curl / curl.exe
    ↓
Stream stdout / stderr
    ↓
Built-in Terminal
```

第一版只解决以下问题：

1. 管理本地 curl 文件
2. 编辑 curl
3. 管理环境变量
4. 执行 curl
5. 实时查看 stdout/stderr
6. 支持 SSE 流式输出
7. 支持停止正在运行的 curl
8. 支持 macOS / Windows

---

# 2. 核心设计原则

## 2.1 保持极简

CurlDesk 第一版不实现：

- HTTP Request Builder
- Method / URL / Header / Body 图形化编辑
- Postman Collection
- HTTP Client
- WebSocket Client
- SSE Client
- SQLite
- 用户账号
- 云同步
- 团队协作
- API 文档生成
- Mock Server
- 自动化测试
- 压力测试

CurlDesk 不负责理解 HTTP。

CurlDesk 负责：

```text
保存 curl
+
编辑 curl
+
执行 curl
+
显示输出
```

---

## 2.2 curl 是唯一请求格式

例如：

```bash
curl -N "{{BASE_URL}}/v1/chat/completions" \
  -H "Authorization: Bearer {{API_KEY}}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3.6-35B-A3B",
    "messages": [
      {
        "role": "user",
        "content": "你好"
      }
    ],
    "stream": true
  }'
```

CurlDesk 不应该把它转换成：

```text
Method
URL
Headers
Body
```

`.curl` 文件本身就是数据。

# 13. Curl Parser

因为：

```go
exec.CommandContext(ctx, executable, args...)
```

需要：

```text
[]string
```

所以需要把：

```bash
curl -N "https://example.com" \
  -H "Authorization: Bearer abc" \
  -d '{"name":"test"}'
```

解析为：

```text
[
  "-N",
  "https://example.com",
  "-H",
  "Authorization: Bearer abc",
  "-d",
  "{\"name\":\"test\"}"
]
```

注意：

这是第一版最容易出问题的地方。

必须正确处理：

- 单引号
- 双引号
- 空格
- JSON
- 多行
- `\` 换行
- Windows CRLF

不要简单：

```go
strings.Fields(command)
```

这是错误的。

需要实现一个最小 Shell-like tokenizer，或者选择成熟、轻量的 tokenizer 库。

但不能真正执行 Shell。

# 16. Goroutine 设计

一次执行：

```text
User Run
   ↓
goroutine
   ↓
exec.CommandContext
   ↓
curl OS process
```

注意：

curl 是操作系统进程，不是 goroutine。

建议结构：

```text
Run
│
├── execute goroutine
│
├── curl process
│
├── stdout reader
│
└── stderr reader
```

第一版不需要：

- Worker Pool
- Task Queue
- Scheduler

用户同时执行几个 curl 不会造成压力。

# 17. Context 生命周期


```go

```

```text

```

```go

```

终止对应 curl。

# 18. stdout / stderr

必须流式读取。

不能：

```go
cmd.Output()
```

否则无法实时显示 SSE。

使用：

```go
stdout, err := cmd.StdoutPipe()
stderr, err := cmd.StderrPipe()
```

然后：

```go
cmd.Start()
```

分别实时读取。

# 19. SSE 支持

CurlDesk 不实现 SSE 协议。

用户自己写：

```bash
curl -N ...
```

curl 返回：

```text
data: {"content":"你"}

data: {"content":"好"}

data: [DONE]
```

CurlDesk 只负责把 stdout 原样转发。

这是重要架构原则：

> CurlDesk does not understand SSE.

---

# 20. 输出读取不要只依赖 Scanner 行模型

虽然简单实现可以使用：

```go
bufio.Scanner
```

但正式 Runner 建议按 chunk 读取。

原因：

部分响应：

```text
data: xxx
```

不一定及时换行。

更好的方式：

```go
buffer := make([]byte, 4096)

for {
	n, err := reader.Read(buffer)

	if n > 0 {
		emit(buffer[:n])
	}

	if err != nil {
		break
	}
}
```

这样可以做到真正实时输出。

# 45. Codex 开发规则

Codex 实施过程中遵循：

1. 优先标准库
2. 不过度设计
3. 不引入数据库
4. 不重新实现 HTTP
5. 不通过 Shell 执行 curl
6. curl 必须作为独立 OS Process
7. 每个 Run 使用 context 控制生命周期
8. stdout/stderr 必须实时读取
9. 所有 Run 必须具有唯一 runID
10. Go 并发代码必须考虑 race
11. RunManager 使用 mutex 保护共享状态
12. 应用退出必须清理子进程
13. Curl Parser 必须有单元测试
14. Environment Resolver 必须有单元测试
15. Runner 必须有测试
16. UI 保持极简
17. 不自行增加产品功能
18. 每完成一个阶段确保项目可运行

# 47. 最终核心架构

始终保持：

```text
                  CurlDesk
                     │
              ┌──────┴──────┐
              │             │
          Workspace      Environment
              │             │
              └──────┬──────┘
                     │
                Curl Editor
                     │
                     ▼
            Variable Resolver
                     │
                     ▼
                Curl Parser
                     │
                     ▼
                 []string
                     │
                     ▼
                RunManager
                     │
              context + Run
                     │
                     ▼
             Process Runner
                     │
          ┌──────────┴──────────┐
          │                     │
        macOS                 Windows
          │                     │
        curl                  curl.exe
          │                     │
          └──────────┬──────────┘
                     │
             stdout / stderr
                     │
                     ▼
                Wails Event
                     │
                     ▼
                 xterm.js
```

CurlDesk 的核心边界必须始终清楚：

> **CurlDesk manages curl. Curl executes HTTP.**

只要坚持这个原则，项目就能够长期保持轻量、简单和可维护。
